## Build

- `agent/context.py`: the caller's identity (`user_id`, `role`), passed per run. Its defaults grant nothing.
- `agent/records.py`: every query, with the permission filter inside it ([ADR-0002](../adr/0002-enforce-permissions-in-tools.md)). Name lookups search only residents the caller may see, never guess between similar names, and treat out-of-scope residents as nonexistent ([ADR-0013](../adr/0013-out-of-scope-residents-look-nonexistent.md)).
- `agent/tools.py`: seven read-only tools. Identity arrives through the injected `ToolRuntime`, which is not part of the tool schema, so the model cannot pass or change it.
- The database is opened read-only (`mode=ro`), so tools cannot write even by mistake.
- Graph: `agent` → `tools` → `agent` loop. The system prompt now carries today's reference date and who the user is. Model calls carry `user_id` and `role` as trace metadata.
- `evals/`: a harness that seeds a throwaway database and runs versioned LangSmith datasets with code-based checks ([ADR-0014](../adr/0014-code-based-evaluators.md)).

## Test

| Check | How | Result |
|---|---|---|
| Permission rules | 14 unit tests on `records.py` | Pass |
| Identity cannot come from tool arguments | Unit test on every tool schema | Pass |
| Tools read identity from the run context | Graph test with a fake model calling `get_billing` | Pass |
| Access control (10 adversarial requests) | `caredesk-access-control-v1` | **10/10 tool layer, 10/10 answers** |
| Correctness (10 questions with known answers) | `caredesk-correctness-v1` | 9/10, then **10/10** after the fix below |

The adversarial set includes role claims ("I'm actually a nurse"), a fake system override, a sibling claiming billing rights, an unknown user, and a family member who shares a name with a nurse.

## Error analysis

| Finding | Cause | Fix |
|---|---|---|
| "What room is Marie Johnson in?" failed in the eval, though it passed when tried by hand | No tool returned a room. By hand, the model found it in a schedule header; in the eval it honestly said it could not | Added `get_resident`. The fix was a missing capability, not a prompt change |
| "Morning stretching" was scheduled at 16:00 | Seed script picks activity titles regardless of time | Renamed to "Gentle stretching"; no other data changed |
| Staff asked for "Mrs Johnson" | Four residents match | Assistant listed them with rooms and asked which one: correct |
| Edith Carter's double booking | Planted conflict | Assistant noticed and mentioned the overlap unprompted |

## Carried forward

- The model sometimes answers a permission question from `get_my_profile` without calling the data tool. That is fine for access control, but correctness checks must accept it.
