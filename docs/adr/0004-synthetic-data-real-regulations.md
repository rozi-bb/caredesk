# ADR-0004: Synthetic operational data, real regulations

- Status: Accepted
- Date: 2026-09-16

## Context

Resident-level operational data is protected health information, so no public dataset exists. We checked the options:

- CMS provider data and the Kaggle mirrors are facility-level (ratings, staffing), not resident-level.
- Synthea generates clinical records, not schedules, visits, or billing.
- Activity-of-daily-living datasets are video and sensor data.

## Decision

- Operational data is synthetic, generated by `scripts/seed_db.py` from a fixed seed.
- Rules come from the real CMS State Operations Manual, Appendix PP (public domain).

## Alternatives considered

- **Synthea**: Java, clinical output, would need heavy conversion for little benefit.
- **LLM-generated data**: not reproducible between runs.
- **CMS facility data**: wrong granularity, and it pulls the product toward nursing-home search, which is out of scope.

## Consequences

- We control the data, including deliberate hard cases (similar names, different access levels, double bookings) that test access control.
- Runs are reproducible, which evaluation needs.
- Contact details use the fictional 555-01xx range and example.org so nothing can match a real person.
- Synthetic data cannot prove real-world accuracy. The README states the data is synthetic.
